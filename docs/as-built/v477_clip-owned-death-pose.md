# v477 As-Built — Clip-Owned Death Pose

Date: 2026-09-29
Status: Complete
Commit: pending
Spec: none — client-presentation-only fix under the CLAUDE.md spec-gate exemption (no protocol,
server state, shared rules, or golden changes).

## Bug

`ModelReactionController.enter_death()` tweened the entity root's `rotation.x`/`rotation.z` by
`DEATH_LEAN_RADIANS` (1.35 rad ≈ 77°) toward the hit direction, while `AnimationController` also
entered terminal `death` on the same entity. The two stacked: corpses stood on end (dead
`dungeon_wolf` in the `companions` showme focus) or tipped up into the air (dead kit skeleton).

## Root cause

The lean was assumed to be the death pose for "legacy models without a death clip". That is false:
every rigged visual already ships a `death` clip that lays the body down. Measured on the current
scenes:

| Scene | `death` clip | Rotation |
|-------|--------------|----------|
| `monster_dummy`, `monster_skeleton` | `pivot` bone, 1 track | 88° roll |
| `monster_quadruped` | `spine` bone, 1 track | 82° pitch |
| `monster_wolf`, `monster_tiny_flyer` | model node, 1 track | 82° roll |
| legacy `character` | `spine` bone, 1 track | 72° pitch |
| kit skeletons | `Death_C_Skeletons` (aliased by `KitMonsterVisual`) | authored |
| kit heroes | Rig_Medium death (via `KitHeroClips`) | authored |

The only visual without an AnimationPlayer is the training doll silhouette
(`TrainingDamageLogBridge.make_silhouette_root`). For that visual the root lean is the entire death
presentation.

## What shipped

- `client/scripts/model_reaction_controller.gd`: `enter_death()` always applies the impact flash
  and the `DEATH_DARKEN`. It skips the root lean when the reaction root's AnimationPlayer has a
  `death` clip (`_has_death_clip()`). The check runs at death time, not at construction, for two
  reasons: kit visuals alias `death` in `_ready`, and a class swap replaces the player model under
  the same `character_visual` root. `enter_death()` also snaps the root back to its base rotation,
  so a hit lean that is still tweening cannot survive under the clip pose.
- Hit reactions (`HIT_LEAN_RADIANS`) are unchanged.
- `client/scripts/showme/visual_capture.gd` (`companions` focus): repaired the call to the removed
  `main._sync_camera_to_player()` (now `_camera_controller.sync_to_player()`), which made the focus
  error out. Added a dead `training_dummy` and a dead `dungeon_mob` (kit skeleton) next to the dead
  wolf. Added a 2.5 s settle before the capture so the terminal clips finish.

## Decision: structural rule, not a data flag

A per-visual flag in `monster_visuals` / `kit_monster_presentation` was considered and rejected.
The flag would be `false` for every rigged visual, and the only `true` case is already identified
by the asset itself: it has no AnimationPlayer. A flag could also disagree with the asset (lean
on + laying clip = the same bug). This is a presentation-ownership rule, not a tuning value, so
the Data-Driven Configuration Policy does not apply. `DEATH_LEAN_RADIANS` remains a code constant
used only by the clip-less fallback.

## Proof

- `client/tests/test_death_pose_ownership.gd` (registered in `scripts/client_smoke.sh`):
  - kit skeleton, legacy dummy, and kit hero (`main._make_remote_player_node`, paladin): after
    death, the `death` clip is playing, the root rotation is unchanged, and the tint is darkened;
  - kit skeleton hit mid-lean followed by death: the root is restored to base;
  - training doll silhouette: the root still leans.
  - Red against the pre-fix controller (all 4 rigged cases leaned the root by 1.35 rad); green after.
- showme `companions` before/after: the kit skeleton lies flat on its back, the dummy lies flat,
  and the wolf no longer stands on its tail. showme `monsters`: living monsters unchanged.

## Known gap

- The `monster_quadruped` (evil fox, used by `dungeon_wolf`) death clip pitches `spine` 82° about
  X, which reads as a nosedive rather than a roll onto the side. This is an asset-clip issue
  (`client/animations/monster_quadruped_fox_anims.tres`, generated by
  `tools/assets/rig_quadruped_monster_glbs.py`), not the reaction lean. Moot since v482: the
  Quaternius wolf replaced this visual and plays its own `Death` clip.
