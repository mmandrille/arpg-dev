## 1. Executive summary

**What went well.** The 26 slices since v460 delivered two large, well-executed programmes.

- **The ADR-0018 art overhaul** replaced every procedural placeholder with CC0 kit art.
  - It retired the legacy 17-bone hero pipeline and removed the last unconfirmed-license assets.
  - It landed in about 20 small, unit-tested client modules. `main.gd` grew by only 4 lines net
    (6,711 → 6,715).
- **The replay-determinism chain (v476–v481)** closed four real live-vs-replay divergence classes.
  - It uses server-authored, stored-only system inputs with parity tests.
  - Live and replay now share one `sessionsetup` path.
- **The authority boundary still holds:** there is no client-side outcome logic.

**What went wrong.** The review cadence slipped by 16 slices, and the depth of this pass shows what
that cost.

- **A new High protocol hole: clients choose their input tick, with no upper bound.**
  - `session_loop.go:372-375` only raises past ticks to the current tick.
  - The schema says `minimum: 0` only.
  - One message with a huge `tick` makes that session's resume, `/state`, `/replay` and
    `make replay` simulate up to that tick, with no cancellation.
- **The determinism lint guards much less than `CLAUDE.md` claims.**
  - Map-range checks cover `sim.go`/`handlers.go` only, which is about 22% of `game/`.
  - It misses an order-dependent tie-break in live code (`skill_aim_nav.go:21`, ranging over the
    `level.entities` map).
- **Test gates are softer than they look.**
  - Client `run_gate` passes a test that died of a GDScript runtime error, as long as the PASS
    sentinel printed.
  - At least one assertion is vacuous (`test_delta_apply.gd:222-231`, `true == true`).
  - Two test files are never run.
  - Three goldens for server-owned formulas have **no Go consumer** (`use_consumable`,
    `shop_appraisals`, `skill_points_and_magic_bolt`).
- **"Protocol schemas are versioned" is nominal.**
  - `state_delta.v8` has been edited in place in 56 commits.
  - v486 resolved 44 live drifts mostly by bending the schema to the server.
- **Process discipline eroded.**
  - Slice numbers collided three times (v461, v464, v476).
  - 10 of 26 slices have no plan, including the v485 protocol change.
  - Four slices lack an as-built.
  - All CI is self-reported (there is no remote CI).
  - The `origin` URL embeds a credential.

**Net:** feature and art velocity were excellent. Correctness defences (the lint, the gates,
goldens, schema versioning) and process hygiene did not keep pace. Scores drop mainly because this
pass looked harder, not because the code got worse overall. Several v460 scores were not earned in
hindsight, for example boundaries at 9.0 with 44 latent schema drifts.

## 3. Cross-cutting themes

1. **Replay is now the product's spine, but its inputs are not fully closed.** v476–v481 proved the
   stored-system-input pattern works. The remaining leaks all break the rule "replay depends only on
   recorded data":
   - client-chosen ticks;
   - env-derived debug mode;
   - live mercenary rows;
   - no stored rules/content version, and resume uses `Reconstruct` instead of `Verify`.

   They need one ADR plus a small ratchet test, not ad-hoc fixes.
2. **Defences that pass silently.** The determinism lint only covers two files and passes on
   type-check failure. Client gates ignore runtime errors. DB tests skip when Postgres is down.
   Goldens exist with no server consumer. Each gives false confidence, and together they explain
   why 44 schema drifts and a dead v468 scenario survived unnoticed.
3. **Contracts drift by in-place edits.** v8 schemas are edited as living documents. `envelope.v8`
   rotted to half the intent list, and client→server intents are never validated live. Either adopt
   a real bump policy (v9 at the next breaking change) or rewrite the invariant to "additive-only
   within v8, enforced by the v486 gate". The current text is simply untrue.
4. **Coordinator debt is concentrated, not diffuse.** Four hotspots hold most of the cohesion
   penalty: `main.gd` `_apply_delta`, `run.py` `execute_step`, `validate_shared.cross_checks()` and
   `sim.go`'s stat aggregation. Each has a clear seam named in its companion report. The ratchet is
   holding the total down, but 20 files are spending their slack.
5. **Parallel-session development needs its own guardrails.** Concurrent worktrees shipped fast (for
   example v482–v486 in one day), but produced number collisions, missing plans and as-builts, and
   self-reported CI. A slice-number reservation step, a remote CI run on `main`, and an enforced
   Godot version would remove most of it.
6. **Graphics perf is unmeasured debt.** Draw calls rose about 4× (97–175 → 499–543). There is a
   761 ms first-spawn hitch. The inverted occlusion throttle is a plausible contributor. The frame
   rate floor holds on the dev host only, and there is no automated perf gate.

## 4. Top 10 recommendations

Tags: **[blocker]** = before the next feature batch; **[minor]** = safe for `$refactor`;
**[future]** = multi-slice.

1. **[blocker · Correctness/Security] Bound the input tick.**
   - Reject, or clamp and record, any `env.Tick` beyond `cur + window` (`session_loop.go:372`).
   - Add a replay max-tick / cancellation guard (`replay.go:227,286`).
   - Add a regression test. See the backend report, Top 5 #1.
2. **[blocker · Security] Remove the credential from `origin`.** Run
   `git remote set-url origin https://github.com/mmandrille/arpg-dev.git`, use a credential helper,
   and **rotate the token**. This is an owner action; agents must not handle the secret.
3. **[blocker · CI] Get `make ci-full` green.**
   - Root-cause the 9 unique/set scenarios that fail only inside the full pack. Likely shared
     account, stash or unique-item state between scenarios.
   - Retire or rewrite `eye_view_weapon_presentation` together with the dead first-person bot
     surface (client Top 5 #2).
   - Diagnose `buyer_offer_cancel_ui`.
4. **[minor · Test] Harden the client gate.**
   - Make `run_gate` fail on `SCRIPT ERROR` / `Parse Error` (`client_smoke.sh:95-118`).
   - Register `test_quest_steward_presentation.gd` and `test_weapon_range_tooltip.gd`.
   - Replace the vacuous asserts in `test_delta_apply.gd`.
   - Expect this to surface hidden failures.
5. **[minor · Correctness] Widen the determinism lint** to all of `game/`, with a `//nolint` baseline
   for existing sites, and make it fail on type-check errors. Fix the `skill_aim_nav.go:21`
   tie-break with sorted ids or an id tie-breaker, and the `unique_chest.go:240` allocation order.
6. **[minor · Correctness] Record gameplay-debug mode on the session** so replay never reads env
   (`sim.go:520`), and unify the two env parsers. Surface errors from `SetSessionMemberConnected`
   and `SetSessionMemberDisconnected` instead of dropping them.
7. **[minor · Golden] Add Go consumers** for `use_consumable`, `shop_appraisals` and
   `skill_points_and_magic_bolt`. Extend `use_consumable` with leveled-potion cases (v460 #3, still
   open).
8. **[future · Contract/Docs]**
   - Write an ADR for the replay contract: server-authored system inputs, which data replay may

   - Decide the protocol versioning policy and rewrite the `CLAUDE.md` invariant to match.
   - Update `envelope.v8` to the 45 decoded intents, or delete it and point CODEMAP at

9. **[minor · Perf]**

   - Switch the ground-loot tint to `ModelTint` (`loot_node_factory.gd:390-396`).

## 5. What "done well" looks like here

- **The replay fixes set the pattern.** Every divergence class became a stored server-authored input
  with a live-vs-replay parity test and a pre-fix red proof (v476–v481).
- **The graphics overhaul shows how to change a lot safely.**
  - Data catalogs came first (`render_presentation`, `kit_*_presentation`, `armor_look`), then small
    leaf modules with focused tests.
  - Each slice committed before/after captures, and each purge came with validator gates (license
    allow-list, budgets, orphan check).
- **The concurrency fixes** (`server_helpers.sh`, `test_db.sh`): verified-own-server readiness and
  per-checkout databases removed an entire class of false CI failures.
- **The v486 gate design:** a leaf module, fast dispatch, and a negative control proving it can
  fail. This is the model for hardening the other silent defences (theme 2).
