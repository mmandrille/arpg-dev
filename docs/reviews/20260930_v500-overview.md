## 1. Executive summary

**What went well.** This is the first review window where the stated goal — "pay down the previous
review's findings before shipping more features" — is actually what the evidence shows happened,
and the specialists verified it commit-by-commit rather than trusting the PROGRESS.md summary line.

- Of the v486 review's 10 ranked recommendations plus its scorecard-level findings, **a clear
  majority are genuinely fixed, with matching commits and tests**: the unbounded client tick
  (`realtime/input_tick.go`, `maxClientTickLead = 2`), the determinism lint's blind spot (now all of
  `game/`, 78 grandfathered sites surfaced and tracked instead of 2 files hiding the rest), the
  client gate's blindness to GDScript runtime errors, the dead `eye_view_weapon_presentation`
  surface (fully retired, zero references left, not patched), the inverted wall-occlusion throttle,
  the three orphaned goldens, a `gofmt` CI gate, and a partial `-race` gate.
- **Process discipline, the worst-scoring area at v486, is fully repaired for this window**: all 14
  v487–v500 slices have a spec, a plan, and an as-built, with zero slice-number collisions — a
  direct fix of v486's single worst Process/SDD finding (3 collisions, 10/26 missing plans).
- **The new `$autoloop` coordinated-batch workflow worked on its first real run**, including
  exercising its own "diagnose and rerun" step for real (one integration fix before the combined
  `make ci` went green), not just on paper.
- The v494–v500 graphics batch itself is clean against the invariants that matter most here: no
  delta-dict bracket access, no new client-side outcome logic, properly licensed CC0 KayKit assets,
  and well-factored one-module-per-concern client code with its own focused tests.

**What went wrong, or is still wrong.** Two kinds of gap survived three independent specialist
passes that were explicitly told to distrust "fixed" claims and check them against the diff.

- **One v486 "High, still open" finding silently dropped off PROGRESS.md's own tracking.** The
  mercenary roster still reads live `Dead`/progression rows and still writes via
  `GetOrCreateCharacterProgression` during replay/build (`server/internal/mercenaryroster/load.go`,
  unchanged in substance since v486 — only a `gofmt` realignment touched it). This was v486's
  backend Top-5 #3 and an explicit "High, still open" finding. PROGRESS.md's current open-gaps line
  for the v486 follow-up lists only "replay max-tick/ctx guard, `origin` credential … record debug
  mode on the session" — mercenary roster is not there. This is the one place in the window where
  a reader of PROGRESS.md would reasonably, and wrongly, believe the replay-input-leak class is
  down to one remaining item (the debug flag) when a second, equally serious one is also still live.
- **The two largest Python monoliths and one protocol-contract rot are completely untouched for the
  third review running.** `run.py execute_step` (4,540 lines) and
  `validate_shared.cross_checks()` (3,188 lines) are both *growing* against their baselines (+14,
  +6 this window alone), and `envelope.v8.schema.json` is still missing 13 of 43 real decoded
  intents (narrower than v486's 21-of-45 gap, but the same structural problem: an unvalidated,
  silently-stale protocol enum). `_apply_delta` in `main.gd` also grew (473→482 lines, 68→71
  branches) rather than getting the `DeltaEventRouter` extraction two reviews in a row have asked
  for.
- **The maintainability ratchet's "touch-to-shrink" rule is being ignored more, not less**: 21 of 35
  grandfathered files are now over their own baseline, up from 20/35 at v486, even though the raw
  total line count is trending down. Slack is being spent broadly (panels, Python tools, test files)
  instead of being paid down when those files are touched — exactly the drift pattern rule 4 of the
  Maintainability Ratchet exists to catch.
- **`make ci-full` was not run at all this window.** The fast pack went green once, on the
  integrated batch. Nobody re-ran the extended matrix to confirm the v486 9+2 failure set is
  actually gone, versus just "reportedly fixed by the refactor commits."

**Net:** this was a genuinely effective paydown window, not a cosmetic one — the specialists caught
real evidence for almost every "resolved" claim and, just as importantly, caught the one place a
real fix was claimed but not delivered (mercenary roster) and the one place a true fix was
under-documented (PROGRESS.md's open-gaps omission). Scores move up from v486 where the evidence
supports it, and stay flat or move down for the untouched monoliths and the unrun `ci-full`.

## 3. Cross-cutting themes

1. **The "yes-man trap" this review was explicitly built to catch caught exactly one real miss, and
   it was a documentation miss, not a code miss.** Every specialist was told to verify claimed fixes
   against the diff rather than trust PROGRESS.md's summary. On every item PROGRESS.md claimed was
   fixed, the code backed it up. The one failure was an *omission*: PROGRESS.md's open-gaps list for
   the mercenary-roster/debug-flag pair silently dropped the mercenary-roster half, even though nothing
   claimed it was fixed. The lesson isn't "don't trust PROGRESS.md" — it's "a tracking list that
   bundles two findings under one line will lose one of them the next time only one gets fixed."
2. **Replay-input integrity is now one leak closed, one leak unchanged, one leak mitigated-not-closed.**
   Client-chosen tick: closed with a test. Mercenary roster: untouched. Replay max-tick/ctx guard:
   still absent, but its only known trigger (the tick hole) is now closed, so the practical risk
   dropped even though the defense-in-depth code didn't change. This is a coherent, trackable set —
   it deserves the single PROGRESS.md open-gaps line the backend report recommends, not a buried
   mention.
3. **"Fix the two files everyone agrees are too big" is now a three-review-old non-starter.**
   `_apply_delta`, `run.py execute_step`, `validate_shared.cross_checks()`, and `sim.go`'s
   movement/AI/projectile region were all named at v460, repeated at v486, and are still either
   unstructured or actively growing at v500. Naming them a fourth time without a scoped, scheduled
   slice is not going to be different from naming them a third time. These need to be slices with
   numbers, not recommendations.
4. **Defense quality beat feature quality this window, and that's the right trade for a 16-slice-late
   review recovery — but it means `make ci-full` is now two reviews unverified.** v486 ran it once
   (FAIL, 31m21s, 11 failures). This window reportedly fixed the failure set but never re-ran the
   extended pack to prove it. The fast pack is not a substitute, and the review says so rather than
   letting PROGRESS.md's "fixed" framing stand in for a rerun.
5. **The new coordinated-batch process (`$autoloop`) is a real capability upgrade, proven once.** It
   ran 14 slices through isolated worktrees in one day, caught and fixed one integration conflict
   before the combined gate, and left zero orphaned worktrees or missing lifecycle rows. Its one gap
   — no explicit reconciliation checklist for a shared JSON catalog touched by multiple slices in the
   same batch (demonstrated live by `town_presentation.v0.json` across four slices) — is a process
   improvement to make now, before a batch hits a catalog conflict the coordinator's manual merge
   judgment can't resolve as cleanly.
6. **Touch-to-shrink is a rule nobody is following, and the ratchet's own count shows it (20→21 of 35
   files over baseline).** The raw total still trends down because a few files shrink a lot
   (`bot_controller.gd`, `sim.go`), while many others creep up a little each time they're touched
   (`market_panel.gd`, `blacksmith_panel.gd`, `fog_of_war_overlay.gd`, `run.py`,
   `validate_shared.py`, `test_protocol.py`). The ratchet's hard ceiling isn't being hit, so CI stays
   green while the rule's actual intent — shrink on touch — goes unenforced.

## 5. What "done well" looks like here

- **Verifying a "fixed" claim means reading the diff, not the commit message or the summary line.**
  Every specialist re-read the actual changed file for each claimed v486 fix and cited the specific
  lines/tests that prove it (e.g. `TestFarFutureClientTickIsRecordedAtCurrentTick` running
  `replay.Verify` end-to-end to prove the tick clamp holds under replay, not just under live input).
- **Honest partial fixes beat silent ones.** The `-race` gate covers only `internal/realtime`, with
  the `internal/http` exclusion commented in the CI script itself, not hidden. The gameplay-debug-mode
  gap now carries a `//nolint` comment admitting it's a known, unfixed risk. Both are better process
  than v486's silent "passes because the sentinel printed" gates.
- **The autoloop batch workflow's failure-recovery step wasn't theoretical.** The v494–v500 batch
  needed one real integration fix before `make ci` went green, and the recorded evidence
  (`PROGRESS.md`, the as-built notes) shows that step actually happened rather than being glossed
  over as "first try, green."
- **Dual-consumer golden discipline held on the one golden actually touched this window**
  (`shop_appraisals.json`): both the Go and Python validators needed zero changes beyond the data
  edit, which is exactly what "goldens are cross-language contracts" is supposed to buy.
