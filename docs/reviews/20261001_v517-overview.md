## 1. Executive summary

The batch is a well-run, well-documented presentation upgrade: seven slices with spec, plan, as-built, and lifecycle rows; new logic landed in small, directly testable modules (14 new GDScript unit gates all registered in the fast smoke); `main.gd` grew by 9 lines net; `inventory_panel.gd` shrank from 1,623 to 1,111 with its baseline lowered; and the authority boundary was not touched.

Two honest caveats. First, runtime proof: the fast CI gate passed, but it ran **zero** of the new client scenarios and the extended matrix was not run, so the boss banners, boss presence, monster windup poses, variant looks, and HUD are covered by unit tests and slice-worktree evidence only. Second, the UI theme migration is half-done: `UiTheme`/`HudStyle` now own the inventory, character, and HUD surfaces, while shop, stash, market, skills, blacksmith, and tooltips keep private style tables, and item-tooltip content is still forked four ways. This is recorded by the slices themselves; it is the right next maintainability target.

The server-side correctness risk from v510 is unchanged and still the most important issue in the repo: realtime input is handed to the sim before the durable append succeeds (`server/internal/realtime/session_loop.go:371-393`). Nothing in this batch addressed or worsened it, and no scheduled slice addresses it.

## 3. Cross-cutting themes

- **A green fast gate is not proof of the new visuals.** The pack of 13 client scenarios predates the batch. Treat v511–v517 runtime behavior as "unit-tested and slice-verified", and run the five new scenarios (and ideally `make ci-full`) before building more on them.
- **Two theming systems coexist.** `UiTheme`/`HudStyle` (token-driven, validated, tested) beside per-panel literals. The catalog is a shared contract with one consumer, extended additively by four slices, with no gate tying client call sites to it.
- **Duplicated sources of truth are accumulating in small places**: rarity colors (`client_constants.gd:38-44` vs `ui_theme.v0.json:36-40`, parity held by a test), boss look (server rules vs client catalog), tooltip content (inventory vs stash/shop/market).
- **Coordinator files are at their allowance.** `main.gd` is 22 lines above its baseline (limit +25); the next edit must extract first. Hook-style additions to `_apply_delta` are the pressure point.
- **Performance claims are bounded by one fast host.** Boss presence (2 → 12–20 draw calls per boss in isolation), HUD (+16 draw calls, 108 → 124), and variant auras are measured only on an Apple M4 Pro at vsync cap; weaker-GPU cost is untested.
- **v510 follow-up status:** replay input durability, replay bounds, rules/debug pinning, reconnect snapshot schema checks, `main.gd`/`sim.go`/`run.py`/`validate_shared.py` hotspots, ratchet touch-to-shrink, and the v506/v508/v509 evidence gaps are all still open (no server diff; client hotspots unchanged or slightly larger). The Postgres-before-DB-tests CI ordering item is closed (`16eab682`).

- Shared presentation data gets a strict schema, a semantic validator, and a test file at birth (`ui_theme`, `boss_presentation`, `monster_variants`).
- As-built notes state what was not measured (isolated-scene boss cost, vsync-capped HUD A/B, town-only variant capture) so a reviewer can see the proof boundary.
- A green fast gate is reported next to an unrun extended gate, never in place of it.
