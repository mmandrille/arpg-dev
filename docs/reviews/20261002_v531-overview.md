## 3. Cross-cutting themes

- **Generation claims have bounded evidence.** The fixed-seed/depth audit repeated identically and its invariants pass, but it is not proof of visual quality, runtime performance, or every possible seed.
- **Resource limits belong at request boundaries and loops.** The replay timeline accepts a caller-controlled tick horizon without a practical bound or cancellation check (`inspect.go:180-189`, `replay.go:286`).
- **Recorded event provenance matters.** Coalescing keeps delta payloads but discards their individual envelope ticks; bot freshness metadata then uses the newest tick for all events (`main.gd:1126-1155,1773-1778`).
- **Durability and replay are coupled.** Inputs can enter the in-memory simulation before database append completes; replay uses current rules instead of a session-pinned version (`session_loop.go:370-395`, `replay.go:89-118`).
- **New code should meet the ratchet.** The encounter composition module exceeds the 600-line new-file target; validator and bot-runner coordinators also remain large.
- **Security/logging finding is baseline-wide.** Raw database and replay errors can reach logs (`session_loop.go:392-395`, `member_lifecycle.go:91-94`, `inspect.go:201-208`). Map to stable classes before logging.

2. **[minor-commit · Med] Split `dungeon_encounter_composition.go` below the file-size ratchet.** Keep behavior unchanged and run focused game coverage plus maintainability.
3. **[minor-commit · Med security] Sanitize raw infrastructure errors before logging.** Retain stable class/correlation details but exclude raw driver/replay text (`session_loop.go:392-395`, `member_lifecycle.go:91-94`, `inspect.go:201-208`).
4. **[future-plan · High] Bound replay timeline work and honor cancellation.** Define a supported tick horizon and test max/overflow/canceled requests.
5. **[future-plan · High] Define durable input acceptance semantics.** Ensure every input applied by simulation is present in replay or rejected/retried with explicit behavior.
6. **[future-plan · Med] Pin rules/content for historical replay.** Persist a content version/hash or immutable snapshot and test replay across a rules revision.
7. **[minor-commit · Med] Add a fail-fast validator for dungeon audit reports.** Keep the collector report-only but make CI able to reject nonempty failures/findings.
8. **[future-plan · Med] Add Go struct-tag/schema parity validation.** Include negative fixtures and begin with live protocol contracts.
9. **[future-plan · Med] Extract ordered state and event phases from `main.gd:_apply_delta`.** Add event-order tests before moving consumers.
10. **[future-slice · Med] Capture the door/wall presentation across representative layouts.** Existing bot completion and audit metrics do not prove visual readability; retain a warning-clean capture and report its limits.

## 5. What "done well" looks like here

- Bound untrusted replay work and propagate request cancellation.
- Make simulation acceptance, durable input history, and replay reconstruction agree.
- Preserve envelope/event provenance through client coalescing.
- Keep newly added modules within the file ratchet and retain focused behavior checks.
- Distinguish deterministic generation, protocol bot flow, visual quality, and performance evidence.
- Keep security-sensitive failures useful through stable error codes without logging infrastructure details.
