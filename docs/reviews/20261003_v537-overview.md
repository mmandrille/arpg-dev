## 1. Executive summary

The batch delivered the owner's playtest corrections: text-only item tooltips, a 25% wider default camera, wider room entrances with a data-owned clearance floor, and solid barrels/crates/tables placed and enforced by the server. It did so without crossing the authority boundary and with prefix-invariant, rule-derived tests.

Its most important finding is not in the new code. Making rooms wider and more crowded exposed three older limits: the player path-search budget is scaled by straight-line distance (a long detour returns `no_path`), the 1.0 nav grid makes a 2.25 opening one cell wide in some alignments, and generation/test cost sits at Go's default 10-minute package timeout (raised to 20m, which hides the trend). The door-approach bug that made closed doors unclickable in new layouts was fixed; the long-route path budget was not.

Runtime proof is bounded: `make ci` is the fast pack; the extended matrix was not run; windowed visual evidence needed retries and shows doors/walls but no prop on a real floor.

## 3. Cross-cutting themes

- **Wider/denser worlds stress distance-scaled budgets.** Both the path search and generation search budgets are tuned to the old geometry.
- **Convention-based structure.** Props, doors and hazards all ride the `walls` channel; consumers filter by `kind`/`source` ad hoc.
- **Layout-pinned tests are a recurring cost.** Three tests/goldens and a scenario seed had to be re-derived; the Test Locking Policy held but needed enforcement by hand.
- **Evidence is bounded.** Fast pack green; extended matrix, a stable perf probe and real-floor prop frames are missing.
