## Summary

The Go server held its architectural baseline cleanly through a 28-slice run dominated by client-side visual work (v421–v446) before returning to gameplay with quest steward hunts (v448). Server authority, protocol v8, determinism invariants, and intent-registry discipline are all intact. The standout backend gain is today's `skill_rules_validation.go` extraction: `rules.go` dropped 464 lines and the validation logic now lives in a focused, independently testable 471-line module. New gameplay domains (unique effects, set items, quest steward) all follow the established micro-module pattern with zero bleedover into `sim.go` or `handlers.go` beyond a single handler registration each.

Structural risks are unchanged from v420: `sim.go` grew 23 lines to 6,635 (now at its ratchet ceiling), `applyMovement`/`advanceMonsterAttack`/`advanceProjectiles` remain in-file, `persistTick` is a ~242-line monolith in `session_loop.go`, and `repos.go` sits at 2,304 lines with no partitioning since v384. `mercenary_character.go` and `rogue_skills.go` are both at exactly 596 lines — four lines under the 600-line ceiling with no headroom for feature additions. A pre-existing flaky test (`TestDungeonTeleportersReplayGolden`) was surfaced during the refactor session and documented as a known issue; the cause is navBudget exhaustion in town navigation introduced between v420 and v448.

## 1. Architecture

The three additions since v420 — `quest_steward_pick_intent`, `corpse_withdraw_item_intent`, and `unique_chest_take_item_intent` — each map to a dedicated handler function. `applyInput` at `sim.go:1107` remains a pure dispatch with zero new `case` blocks.

**[Strength]** Tick phase orchestration in `tick_results.go` is clean. The `TickResultsProfiled` entry point is the canonical phase host. No v421–v448 slice injected code directly into `TickResultsProfiled`; all new hooks attach through existing phase slots.

**[Strength]** Quest steward follows the micro-module pattern correctly. The feature is split across five focused files: `quest_steward.go` (217 lines), `quest_steward_rules.go` (180 lines), `quest_steward_rewards.go` (122 lines), `dungeon_steward_hunt.go` (46 lines), and `quest_turn_in.go` (68 lines). The handler `handleQuestStewardPick` lives at `quest_steward.go:116` and registers via one line in the handler map.

**[Strength]** Unique effects and set items are correctly modularized. `unique_effects.go` (582 lines), `unique_resource_effects.go` (266 lines), `unique_survival_effects.go` (366 lines), `unique_debuff_replication.go` (131 lines), and `set_items.go` (351 lines) are all under the ceiling with focused responsibilities.

**[Strength]** `skill_rules_validation.go` extraction (today) is a genuine 16-function refactor: each validator is independently callable, `validateSkillRules` is the unambiguous entry point, and `rules.go` dropped to 2,783 from 3,237.

**[High]** `sim.go` phase bodies remain in-file. `applyMovement` (`sim.go:2764`), `advanceMonsterAttack` (`sim.go:3206`), and `advanceProjectiles` (`sim.go:3586`) account for ~820 lines of per-phase logic. `sim.go` stands at 6,635 — up 23 from v420 and at its ratchet ceiling. Any substantive new gameplay phase will breach the ceiling.

**[High]** `rules.go` still a loader/validator coordinator at 2,783 lines. It owns loading for monsters, items, shops, bosses, survival skills, unique items, set items, and quest steward. Steward and set-item loaders joined the existing chain rather than landing in their own `*_rules.go` files.

**[Med]** `persistTick` is a ~242-line event/change monolith at `session_loop.go:636–877`. The function absorbed `resource_wallet_update`, `teleporter_discovery_update`, and implicit quest event handling since v420. The `deferNonCritical` path adds conditional dispatch inside an already dense switch.

**[Med]** `repos.go` unchanged at 2,304 lines. No partitioning since v384.

## 2. Technical

**[Strength]** Determinism posture intact. `time.Now()` and bare `math/rand` return zero hits in hot-path `game/` files. Seeded RNG, sorted iteration helpers, and `//nolint:determinism` annotation discipline are all in place.

**[Strength]** Quest steward reward path looks correct. `handleQuestStewardPick` at `quest_steward.go:116` consumes the trophy item, resolves family offers, and rolls a magic+ item at `quest_source_depth`. The `questSourceDepth` field is set at trophy pickup time (`sim.go:1764–1766`) — capturing the actual dungeon depth, not the current player depth at turn-in. This is correct.

**[Strength]** New domain test files follow the focused companion test pattern. v448 additions include `quest_steward_test.go`, `unique_effects_hunger_test.go`, `unique_debuff_replication_test.go`, `set_items_test.go`, `unique_items_validation_test.go` — all under 300 lines and independently testable.

**[Med]** `TestDungeonTeleportersReplayGolden` is a pre-existing flaky test (surfaced today). The failure mode is navBudget exhaustion in town navigation after teleporting back from level −3 — the town pathfinding budget of 30,000 ticks is sometimes insufficient given dungeon layout changes introduced between v420 and v448. Documented in `PROGRESS.md` as a known issue.

**[Med]** v448 as-built explicitly defers the full client bot proof for the steward family picker click interaction (`quest_steward_pick_intent` round-trip from the client side). The protocol bot covers this intent; the client side has a `bot_click_offer` method in `quest_steward_panel.gd` but no CI scenario drives it end-to-end.

1. **[High · Maint]** Extract `applyMovement` and `advanceMonsterAttack` to dedicated phase files (`movement_phase.go`, `monster_attack_phase.go`). `sim.go` is at its ratchet ceiling; any new combat feature that touches these phases will breach it. Both blocks are ~400 lines, callable unchanged from `tick_results.go`.

2. **[High · Maint]** Continue `rules.go` loader partition into per-domain loader files. At 2,783 lines, it still owns 15+ domain loaders. The skill extraction pattern proves the approach. Next candidates: unique item loader, set item loader, shop validation extraction.

3. **[Med · Maint]** Decompose `persistTick` at `session_loop.go:636–877` into per-Op persist modules. The function is 242 lines of dense switch; extract `persistEvents(...)` and `persistChanges(...)` helpers or a `tickPersistor` value type.

4. **[Med · Maint]** Pre-emptively split `mercenary_character.go` (596 lines) and `rogue_skills.go` (596 lines) before they breach the 600-line ceiling. `mercenary_character.go` has a clean split between hire/dismiss and combat-stat pipeline; `rogue_skills.go` between passive-execute and direct-cast skills.

5. **[Med · SDD]** Write ADR for the quest system. The steward hunt introduced design decisions (trophy scoping, family offer generation, `quest_source_depth` wire field, turn-in pipeline) that will constrain future quest and NPC interaction types. An ADR prevents drift.
