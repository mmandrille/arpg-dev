## Summary

This window's backend work went into **replay determinism**. v476–v481 closed four real divergence classes:
- wall-clock load shedding
- member setup order
- co-op leave/rejoin
- lost quiet ticks

Each is now a **stored-only, server-authored system input** (`inputdecode/system.go:10-25`) with a dedicated live-vs-replay parity test. `sessionsetup` is now shared by live and replay (`sessionsetup.go:113-135`), which removes a whole class of "replay builds the sim differently" bugs. `sim.go`, `session_loop.go` and `repos.go` all shrank for real.

**The replay contract is still open at its edges, and the most serious hole is new in this review:**
1. **Clients choose the tick their input runs on, with no upper bound.** Replay loops up to the largest recorded tick. One authenticated message with a huge `tick` makes resume, `/state`, `/replay` and `make replay` for that session simulate for hours.
2. Gameplay-debug mode affects world construction and intent acceptance, but it comes from the environment of whichever process runs the sim. It is never recorded on the session.
3. The determinism lint covers 22% of `game/` and only one of three map-range forms. It already misses an order-dependent tie-break in live code.
4. Mercenary roster load reads live, mutable alt-character data at replay time, and it writes to the DB while doing so.

Persistence failures are fail-open by design (logged plus a metric), but several replay-critical writes discard their error entirely. CI runs no race detector, even though `realtime` is concurrent.

## 1. Architecture

**[Strength] The authority boundary holds.**
- `handleClientMessage` overwrites `ActorPlayerID` from the connection, never from the payload (`realtime/session_loop.go:356`).
- System inputs cannot be submitted by clients: they are absent from `IsClientIntent`/`Decode` (`inputdecode/system.go:10-25`).
- No outcome is computed client-side.

**[Strength] Live and replay share one setup path.** `NewHostSim` fixes the order of member, roster, companion and corpse loading as a replay contract (`sessionsetup/sessionsetup.go:113-135`). Both `realtime.buildSessionSim` (`session_loop.go:84-115`) and `replay.sessionStartSim` (`replay/members.go:156-196`) consume it. This is the right structural fix for v477/v478-class drift.

**[Strength] Intent registry discipline held.** `applyInput` is a 13-line registry lookup (`sim.go:1101-1113`), and every intent lives in `inputHandlers` (`handlers.go:25-72`).

**[High] Input scheduling tick is client-controlled and unbounded.**
- The server clamps only past ticks: `tick := env.Tick; if tick < cur { tick = cur }` (`session_loop.go:371-375`). `env.Tick` is a client `uint64` (`protocol.go:41`), and the schema allows any `minimum: 0` integer (`shared/protocol/envelope.v8.schema.json:47`).
- The row is persisted with that tick (`session_loop.go:381-395`). `StoredInputs` takes the max tick (`replay/replay.go:227`), and `replayTicks` loops `for t := 0; t <= throughTick` (`replay/replay.go:286`).
- Effect: one message with `tick: 1e9` makes every later `Reconstruct` simulate about 3 years of ticks, and `Reconstruct` has no context cancellation. That covers session resume in `Hub.Run` → `loopForSession` → `buildSessionSim`, the debug endpoints, and CI replay.
- The same row also sets `durableThrough` into the future (`loop_lifecycle.go:114-118`). That disables v481 quiet checkpoints for the rest of the session, and the buffered input never runs live.
- There is no test for future-tick bounds (a grep of the `realtime`/`http` tests finds none).

**[Med] Gameplay-debug mode is a replay input that is never recorded.**
- `NewSim` initialises `gameplayDebug` from `os.Getenv` (`sim.go:520`, `sim.go:896-903`) before town presets are placed. The debug chest is skipped or placed during construction, which shifts every later entity ID (`sim.go:842`).
- All debug intents are accepted or rejected on the same flag (`bishop_debug.go:54,106,118`; `bishop_loot_debug.go:102,137,182`).
- Live then overrides the flag from `config` (`session_loop.go:94,107`). Replay passes `configure=nil` (`replay/members.go:166`), so it runs with whatever env the replay process has. `scripts/ci.sh:418` re-exports `ARPG_GAMEPLAY_DEBUG` to paper over this, but `make replay` does not (`make/agents.mk:15-17`), and bot/ci sessions default it to `true` (`scripts/ci.sh:23`).
- The two parsers disagree. `config.getenvBool` uses `strconv.ParseBool` (`config/config.go:84-91`); `gameplayDebugEnabledFromEnv` accepts `yes/on` but not `t/True` (`sim.go:897`).
  - With `ARPG_GAMEPLAY_DEBUG=yes` in a non-local env, the prod guard passes (`config.go:64`), yet the sim still places the debug chest entity.
- Resume calls `SetGameplayDebug` *after* `Reconstruct` (`session_loop.go:94`). That re-runs `seedUniqueTestChests` and refills emptied chests with freshly allocated IDs (`unique_chest.go:250-258`). The `sessionsetup.go:117-120` comment warns against exactly this ordering.

**[High, still open] Mercenary roster is read from live rows at build/replay time.**
- `mercenaryroster.LoadIntoSim` lists the account's current characters, filters on the current `Dead` flag, and loads current progression and items (`mercenaryroster/load.go:18-46`). A session replayed after an alt levelled or died builds a different hire roster.
- It also calls `GetOrCreateCharacterProgression` (`load.go:28`), so **replay and the debug `/state` endpoint can write to the DB**.
- PROGRESS lists this gap. It is the last "not snapshotted" member input after v478 fixed corpses.

**[Med] Resume trusts `Reconstruct` blindly, and nothing pins the rules/content version to a session.**
- `buildSessionSim` uses `Reconstruct`, not `Verify` (`session_loop.go:89-95`), and nothing records a rules or content version (a grep for `rules_hash|rules_version` finds nothing in `internal/` or `migrations/`).
- After a rules change, resuming an old session silently replays its inputs under the new rules. Players may re-enter a state they never saw.

## 2. Technical

**[Strength] Load shedding is deterministic by construction.** The policy is injectable (`realtime/load_shed.go:24`), the directive is encoded before it is applied, and shedding is skipped if encoding fails (`load_shed.go:47-54`). `load_shed_replay_test.go` pins a real `benchmark_mixed_arena` seed.

**[Strength] Stop/resume ordering is correct.** `stop()` waits for the tick goroutine before writing the final checkpoint (`loop_lifecycle.go:56-73`). `loopForSession` waits on `stopDone` before building a successor (`hub.go:104-111`).

**[High] The determinism lint is much narrower than its documentation claims.**
- The map-range pass runs only on `sim.go` and `handlers.go` (`cmd/determinism-lint/main.go:32-35`). That is 8,118 of 36,421 `game/` lines (22%).
- Even there it flags only `k, v` ranges. `for _, v := range m` is explicitly exempted with an incorrect rationale (`main.go:124-128`), and key-only ranges are never flagged.
- A type-check error makes the lint **pass silently** (`main.go:108-110`, `continue`).
- Live code it cannot see:
  - `skill_aim_nav.go:21-38` picks the "nearest" auto-nav target over `range level.entities` with a strict `<`. Equal `along` ties resolve by map order, which is a real replay hazard for stacked or symmetric monsters.
  - `unique_chest.go:240-258` calls `s.alloc()` inside nested map ranges. This is latent while only one chest exists (`shared/rules/interactables.v0.json`).
- It also does not flag `os.Getenv` in `game/` (see the gameplay-debug finding above).

**[Med] Replay-critical persistence errors are dropped or fail-open.**
- `SetSessionMemberConnected` discards its error, and that write carries the `joined_tick` v480 replay depends on (`session_admission.go:29`). `SetSessionMemberDisconnected` does the same (`session_loop.go:190`, `hub.go:84,93`). A stuck `connected=true` row then yields `member_already_connected` on reconnect (`hub.go:65-75`).
- Client inputs and system inputs are applied to the sim even when their `AppendInput` fails; only a log and a metric record it (`session_loop.go:395-398`, `member_lifecycle.go:91-94`). Nothing marks the session "replay integrity lost".

**[Med] DB calls on the tick path have no deadline.** All realtime writes use `context.Background()` (`persist_batch.go:58`, `session_loop.go:526`, `member_lifecycle.go:91`). They run synchronously inside `doTick` (`session_tick.go:59-66`), so a stalled Postgres freezes every session tick.

**[Med] No WebSocket frame or rate limits.**
- `CheckOrigin` always returns true (`hub.go:39`).
- There is no `SetReadLimit` and no per-client input rate limit (grep over `realtime/`, `http/realtime.go`).
- The `seen` and `received` maps grow for the whole session (`session_loop.go:370,380`).
- These are acceptable under dev-token auth, but they are prerequisites before any non-local deployment.

**[Low] Auth is dev-grade, as intended.**
- The in-memory `TokenStore` evicts only on lookup of an expired token, so it grows without bound (`auth/tokens.go`, `Lookup`).
- The debug-token comparison is not constant-time (`http/inspect.go:96`).
- `through_tick` on `/replay/timeline` is unbounded (`inspect.go:180-187`), but it sits behind the debug token.
- `config.Validate` correctly refuses default tokens outside local (`config.go:63-74`).

**[Low] `shouldApplyOverloadDegradation` is a tautology.** Its final `return` fires on any path or movement activity, so the first two checks are dead (`tick_guardrails.go:28-40`).

**[Low] Dead no-op branches.** `_ = inputTypes` appears at `session_loop.go:411` and `fanout_coalesce.go:56`.

**[Low] Migration runner has no advisory lock.** Concurrent boots against one DB race to a PK violation and fail boot; no corruption results (`store/store.go:55-104`). Migrations are otherwise healthy: each runs in its own transaction, embedded, 0001–0031 with no duplicate numbers.

## 4. Documentation

**[Strength]** Every backend slice in the window has a spec, and most have a plan (v472, v476, v478–v481). v485 and v486 have specs only, and v485 documents why. Each has an as-built with explicit residual gaps. `docs/CODEMAP.md:24-27` already lists `sessionsetup`, `loop_lifecycle`, `inputdecode/system.go` and the replay parity tests.

**[Med] The replay contract has no ADR.** Five server-authored input kinds (`system_load_shed`, `system_member_join/leave/rejoin`, `system_tick_checkpoint`) and their tick semantics are documented only across five as-builts. ADR-0001 D8 predates all of them. The unrecorded debug flag and the missing rules pin are undocumented contract gaps.

**[Med] The protocol-versioning invariant was quietly violated.** v486 found **44** live-payload drifts from the Go server, including required-set changes such as `boss_phase` requiring `duration_ticks`. These were fixed by editing `*.v8` schemas in place (`docs/as-built/v486_live-payload-schema-gate.md`), which contradicts CLAUDE.md's "Protocol JSON schemas are versioned". There is still no Go-side schema test: `go.mod` has no JSON-schema dependency, and the gate lives only in the Python bot at CI step 9.

**[Low]** `determinism-lint`'s header correctly says hot-path files only. CLAUDE.md's "Enforced by `make lint-determinism`" oversells it.

## Top 5 backend refactors

1. **[High · Correctness/Security] Bound the client scheduling tick.**
   - Clamp `env.Tick` to `[cur, cur+N]`, with N a small, documented runner constant.
   - Reject inputs beyond that window, or clamp them and record the clamped tick.
   - Add a `ws_test` / `session_loop_test` case for far-future ticks.
   - Make `replayTicks` honour `ctx`.
   - Add a sanity cap in `StoredInputs` (max tick ≤ last event/checkpoint tick + N) so already-poisoned sessions fail fast instead of hanging.
2. **[High · Determinism] Make the determinism lint real.**
   - Run the map-range pass on every non-test `game/*.go` file.
   - Flag key-only and value-only map ranges too, suppressed via the existing `//nolint:determinism` comments.
   - Fail on type-check errors.
   - Ban `os.Getenv` in `game/`.
   - Then fix `skill_aim_nav.go:21` (stable tie-break by entity ID) and `unique_chest.go:240` (sorted levels and entity IDs).
3. **[High · Replay] Snapshot the remaining live-read replay inputs.**
   - Record the mercenary roster in the session-start snapshot, the way v478 did for corpses, and remove the `GetOrCreate` write from the replay path.
   - Record `gameplay_debug` on the session row, and make replay read it from there, not from env.
   - Delete `gameplayDebugEnabledFromEnv` and use the single `config` parser.
   - Pin a rules/content hash per session, and have resume use `Verify` or refuse on mismatch.
4. **[Med · Reliability] Stop dropping replay-critical write errors.**
   - Log and meter `SetSessionMemberConnected/Disconnected` (`session_admission.go:29`, `session_loop.go:190`).
   - Give tick-path DB calls a bounded context.
   - Add a per-session "replay integrity lost" flag set on any `AppendInput` failure.
   - Add `go test -race ./internal/realtime/... ./internal/http/...` to CI.
   - Make DB-backed tests fail rather than `t.Skip` when `ARPG_DATABASE_URL` is set, e.g. `store_test.go:33`, `ws_test.go:40`.
5. **[Med · Maint] Split `sim.go` by phase and gate formatting.**
   - Move the movement, monster-AI and projectile region (`sim.go:2820-3700`) and the stat aggregation (`sim.go:5768-6015`) into phase files, as pure moves in the style of `d69e16e5`.
   - Split `persistTick` into per-domain projectors.
   - Run `gofmt -w` once and add a `gofmt -l` CI step.
