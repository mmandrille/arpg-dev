## 1. Architecture

- **[Strength] Authority boundary intact.** No batch commit touches `server/`, `shared/protocol`, `shared/rules`, or `shared/golden` (verified via `git show --stat b9d71574`: 176 files, all client, shared/assets, tools, docs, scripts). The boss and monster presentation work is keyed off existing wire fields (`boss_template_id`, `is_boss`, `rarity`, `visual_scale`, `monster_attack_windup`, `entity_spawn`).
- **[Low] Dead-weight server visual metadata for bosses.** `shared/rules/boss_templates.v0.json:15-20` still carries `visual.model/color/scale/model_pool`, and `server/internal/game/dungeon_population.go:105-110` still rolls a seeded `model_pool` pick and puts it on the wire. v512 now overrides model, scale, and tint on the client by `boss_template_id` (`client/scripts/boss_presentation_loader.gd:55-60`, `:75-85`), so for catalogued bosses the server-rolled model/scale/color are ignored. `rules.go:2393-2397` still validates the pool. This is two sources of truth for boss look; removing it is a rules-shape/protocol decision, not a drive-by edit (the RNG is a separate seeded stream, but `visual_model` is wire data and goldens/scenarios may pin it). The v512 as-built records the follow-up (`docs/as-built/v512_boss-presence.md`, Limits).
- **[High] Input reaches the sim before it is durable (carried from v510, still open).** `server/internal/realtime/session_loop.go:371-393` appends the input to `l.buffer[tick]` and calls `noteDurableLocked` under the lock, releases the lock, and only then calls `store.AppendInput`; on failure it increments a metric and logs (`:390-393`) with no rollback. `session_tick.go:15-22` drains that buffer into `TickResultsProfiled` regardless. A failed append yields live gameplay the replay log cannot reproduce. Needs a design decision (reject/retry/close-session) and a failure-path test before touching it.
- **[Med] Replay has no horizon or cancellation (carried, open).** `server/internal/replay/replay.go:265-295` loops `for t := 0; t <= throughTick` with no context check; `server/internal/http/inspect.go:180-189` accepts any non-negative `int64` for `through_tick`.
- **[Med] Replay inputs do not pin rules/content revision or the gameplay-debug flag (carried, open).** Per v510, reconstruction takes whatever rules the process loaded, so a rules edit between recording and replay can silently change the result. This is the v510 finding (`sim.go:522,898-904`); it was **not re-derived** in this review and is carried as unverified-but-unchanged (no server diff).
