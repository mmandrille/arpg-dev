## Top 5 client refactors

1. **[High · Maint]** Extract `_apply_delta` event fan-out into a `DeltaEventCoordinator` module (`main.gd:1286–1742`, 456 lines). The steward hunt, combat, skill, and Bishop event branches in the fan-out loop are now numerous enough that a sequence-order bug or protocol rename will silently affect unrelated features. Extract to a module receiving the events array and a narrow dispatch interface, not `self`. This is the same refactor called at v408 and v420 — it has compounded by 86 more lines since last review.

2. **[High · Maint]** Resolve the `inventory_panel.gd` ratchet breach (actual 1,527 vs baseline 1,516). Begin the paper-doll / drag-drop / tooltip extraction flagged since v408. A first isolated step: extract the `_build_item_tooltip_*` cluster into `inventory_tooltip_builder.gd` following the `character_stats_breakdown.gd` pattern.

3. **[Med · Maint]** Decompose `stash_panel.gd` before it breaches ceiling (at baseline+25, 1,180 lines). The identical `_draw_item_icon` / item-loading / `show_status` blocks duplicated across `shop_panel.gd`, `stash_panel.gd`, and `market_panel.gd` are the best extraction target — an `ItemSlotRenderer` helper would reduce each panel by ~80–120 lines.

4. **[Med · Maint]** Replace `_steward_hunt_state: Dictionary` at `main.gd:283` with a typed `class_name StewardHuntState extends RefCounted`. Analogous to the deferred `ConnectionRecoveryContext` recommendation. Blocks silent key-name drift across the three mutation sites.

5. **[Med · Test]** Complete the v448 deferred `quest_steward_pick_intent` end-to-end client CI proof. `quest_steward_panel.gd:110` has a `bot_click_offer` method; a pinned-seed `99_steward_family_pick.json` client scenario would close the coverage gap noted in the v448 as-built.
