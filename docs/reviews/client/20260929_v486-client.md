**Date:** 2026-09-29
**Scope:** Godot thin client, v461–v486 vs the v460 baseline (`e75e64d0`, 70 commits). Covers the
ADR-0018 graphics overhaul: v469 art baseline, v470 render baseline, v471/v473 KayKit dungeon kit,

fallback*), review branch `claude/review-v486`. No source changes in the worktree. The only dirty

**Stats:** 404 tracked `.gd` files, **74,044** lines. Of those, `client/scripts` has 280 files /
54,562 lines, and `client/tests` has 118 `test_*.gd` / 19,374 lines. `client_smoke.sh` has 119

`main.gd` is **6,715** lines, with 499 funcs, 194 top-level vars and 124 `preload` consts.

## Summary

The ADR-0018 overhaul was delivered the right way. Roughly 20 focused modules each have a static
loader and a direct unit test: `ModelTint` 18 lines, `ArmorLook` 171, `KitPieceLibrary`,
`DungeonKitWallBuilder` 106, `DungeonKitFloor` 131, `KitMonsterVisual`, `HeroCorpseVisual` 84,
`RemotePlayerClassSync` 53, and `SceneLightingRig` 55. Across 26 slices of heavy visual churn,
`main.gd` grew by only **+4 lines** (6,711 → 6,715). The thin-client authority boundary is still
intact.

That is where the good news ends. The coordinator debt the v460 review ranked #1 was not touched:
`_apply_delta` is still 473 lines with 68 `event_type ==` branches. The overhaul also left real
defects behind:
- a client-bot scenario that asserts state no code has produced since v468;
- a wall-occlusion "throttle" that never throttles in combat and runs O(monsters × walls) GDScript
  loops per frame and per monster spawn;
- ground loot still using the flat, untextured tint that v474 fixed everywhere else.

The test harness also cannot detect GDScript runtime errors, so "does not crash" tests are
unfalsifiable.

## 1. Architecture

**[Strength]** The thin-client boundary holds.
- No client code mutates HP or other outcomes.
- The only `randf*` calls are camera shake (`camera_impact_feedback.gd:17–19`).
- Local-player HP, mana and scale come solely from authoritative upserts (`main.gd:1863–1918`).
- Prediction hard-snaps to the server position (`main.gd:1907–1911`).
- Commerce panels (`inventory_panel`, `shop_panel`, `stash_panel`, `market_panel`) have no network
  access. They emit signals, and `main.gd:3903–4054` wires them.

**[Strength]** ADR-0018 modules follow the static loader pattern (agent rule 7). There are no
autoloads, and 44 scripts use `static var` loaders. The render baseline is fully data-driven:
`render_presentation.v0.json` holds key light, tonemap, SSAO, glow, fog and quality tiers.

**[Strength]** `ArmorLook` (`armor_look.gd:1–10, 131–146`) puts armor color in the material
*detail* layer. `ModelReactionController` owns `albedo_color`, and both edit the current override in
place. The two therefore compose instead of fighting, and `test_armor_look.gd:77`
(`_test_tint_survives_hit_flash_and_regear`) proves it. `RemotePlayerClassSync.swap_model`
(`remote_player_class_sync.gd:20–32`) correctly disposes and rebinds the animation and reaction
controllers after a class swap.

**[High]** The `_apply_delta` event fan-out is unchanged since v460. It spans `main.gd:1296–1768`
(473 lines, 68 `event_type ==` branches). Presentation is still dispatched on hardcoded skill ids
inside it:
- `"charge"` :1373
- `"earthbreaker"` :1397
- `"heal"` :1412, :2393
- `"pinning_shot"` :1449
- `"dash"` :1456
- `"poison_stab"` in replay pacing :3810

These ids bypass `shared/assets/skill_presentations.v0.json`, so every new skill visual still means
another edit to the 6.7k-line coordinator.

**[Med]** `main.gd` sections are mislabelled grab-bags.
- `# --- scene construction (placeholder primitives)` covers `main.gd:3853–6044`, 2,191 lines.
  After v484 there are almost no placeholders left in it.
- `# --- bot API` covers `main.gd:6044–6682`, 638 lines of bot introspection inside the production
  coordinator.

**[Med]** `bot_facade.gd` reaches into `main.gd` privates through reflection. `_member(owner, name)
→ owner.get(name)` is used 59 times (`bot_facade.gd:324–327`), and `has_method` duck typing appears
159 times across scripts, 113 of them in `bot_facade`/`bot_controller`. A renamed field silently
returns `null` instead of failing. §2 shows this already hid dead first-person hooks.

**[Med]** Shared data is read from outside the Godot project.
`ProjectSettings.globalize_path("res://").path_join("../shared/…")` appears in 44 files. This works
from the repo checkout but cannot work in an exported `.pck` build, which contradicts ADR-0001's
"turnkey export" goal. No export preset exists to catch it.

**[Low]** Ordering inversion between snapshots and deltas.
- `_handle_message` applies `session_snapshot` immediately but queues `state_delta`
  (`main.gd:1121–1128`).
- Deltas that arrived *before* the snapshot in the same `poll()` are therefore applied *after* it,
  including after `_clear_level_entities()` (`main.gd:1069–1076, 1145–1150`).
- The server does send mid-session snapshots on co-op join and on `client_ready`
  (`server/internal/realtime/session_loop.go:172–173, 343–344`).
- State converges, because the queued ops are older upserts. Their events (damage numbers, audio,
  `level_changed` side effects) still replay on top of the fresh snapshot, and no test covers it.

## 2. Technical

**[High]** Stale client-bot scenario: `tools/bot/scenarios/client/105_eye_view_weapon_presentation.json`
(extended tier, so it runs in `ci-full`).
- It asserts `equipment_visuals.eye_view.main_hand.{active,visible}`, `rig_active` and `socket_parent`
  through `bot_eye_view_assertions.gd:7–38`.
- Since `98105010` (v468, "delete fake FP rig"), `EquipmentVisuals.get_debug_state()` returns only
  `equipped_visuals`, `armor_look` and `warnings` (`equipment_visuals.gd:114–124`).
- Nothing emits `eye_view`, so the assertion must fail as `active want=true got=false`. The
  `ci-full` result should confirm this.
- Related dead hooks: `bot_facade.gd:280–281` probes `first_person_animation_controller` and
  `record_first_person_attack`, which exist nowhere. `combat_local_attack_presentation.gd:38,49`
  still carries the `first_person_anim` and `first_person_recorder` parameters.

**[Med]** The wall-occlusion throttle is inverted and runs on hot paths.
- `WallOcclusionFade.sync` skips a rebuild only when *nothing* changed **and** fewer than
  `min_rebuild_interval_frames` (2) frames have passed (`wall_occlusion_fade.gd:29–38`).
- Any monster moving ≥0.01 u changes `_target_signature` (`:148–156`). In combat it therefore
  rebuilds **every frame**.
- The targets are *every* live monster on the level, not just visible ones
  (`wall_occlusion_runtime.gd:19–30`). The rebuild is an O(targets × walls) GDScript loop over
  Dictionaries (`:56–80`), followed by a pass over every wall mesh (`wall_renderer.gd:480–487`).
- It is driven from `_refresh_monster_health_bar_visibility` (`main.gd:2633–2644`). That function
  runs per frame (`main.gd:1108`) and also once **per new monster health bar**
  (`main.gd:2618–2631`, together with a physics raycast via `_pick_entity_at_mouse`).
- A 36-monster first spawn therefore does 36 full occlusion resolves plus 36 raycasts inside one
  delta. That is a credible contributor to the recorded `d_upsert_m` spike (169 ms) and
  `process_ms` hitch (761 ms). This is a hypothesis to profile, not a measured fact.
- In chest view, `apply_occlusion_fades({})` also runs unthrottled every frame
  (`wall_occlusion_fade.gd:22–25`).
- The throttle has no test.

**[Med]** Ground loot missed the v474 tint fix.
- `LootNodeFactory.apply_model_tint` still replaces every material with a flat
  `StandardMaterial3D` (`loot_node_factory.gd:390–396`). That is the exact bug `ModelTint`'s header
  (`model_tint.gd:1–3`) says it fixed.
- The ground models are still Poly Pizza / `gen_glb` `fallback_equipment_*` assets
  (`loot_node_factory.gd:93–118`, manifest provenance). ADR-0018 D10 says these are retired from
  shipped visuals. The ADR rollout table does acknowledge "ground loot still legacy".

**[Med]** Agent rule 8 is violated in the hottest delta path. `_upsert_entity` does
`str(e["id"])` (`main.gd:1857`) and `e["type"]` (`:1863, 1933–1976`) on the change payload, even
though `entity_type` was already read via `.get()` at :1856. An `entity_spawn` without `id` or
`type` raises a script error mid-delta. The malformed-delta test never sends that case (see §3).

**[Low]** Every monster spawn allocates its materials twice. `_apply_model_tint` duplicates each
mesh material (`main.gd:5570, 5969–5973`). `ModelReactionController._capture_meshes` then
duplicates it again and replaces it (`model_reaction_controller.gd:150–170`), so the first copy is
garbage. Faded kit wall pieces also keep their private material copy forever
(`wall_renderer.gd:500–507`), which slowly kills material sharing.

**[Low]** Latent multi-surface and shared-resource hazards.
- `ModelTint`, `ArmorLook` and `ModelReactionController` read only surface 0
  (`model_tint.gd:11`, `armor_look.gd:153`, `model_reaction_controller.gd:166`). They then set
  `material_override`, which collapses multi-material meshes. This is safe today only because the
  kit pieces are single-surface and v482 palette-baked the beasts.
- `KitMonsterVisual._alias_clips` adds aliases to the *shared* imported `AnimationLibrary`
  (`kit_monster_visual.gd:47–61`). If two catalog keys share a GLB with different
  `clip_profile`s, the first spawn wins.
- `_apply_impact_flash` dereferences `mesh_node` before its null check
  (`model_reaction_controller.gd:242–244`).

**[Low]** The rendering budget is structural.
- Floors are MultiMesh (`dungeon_kit_floor.gd:116–129`, **[Strength]**).
- Walls instantiate one scene per piece *per thickness row*, with non-uniform scaling
  (`dungeon_kit_wall_builder.gd:38–75`). Every piece is also a shadow caster under the 60 m
  directional shadow (`render_presentation.v0.json` `key_light`).
- This is the likely source of the ~4× draw calls noted in PROGRESS. Merging each wall's pieces
  into one mesh would keep the per-wall occlusion/pick identity the builder comment wants to
  preserve.

### Test quality

**[High]** Client gates cannot see GDScript runtime errors.
- `run_gate` checks the exit code, the PASS sentinel and `[gdtest] FAIL`
  (`scripts/client_smoke.sh:95–118`). Nothing in `scripts/` or `tools/bot` greps for
  `SCRIPT ERROR`.
- In headless `--script` mode, a runtime error aborts only the current function. Every assertion
  after it silently disappears, and the gate still passes.
- `_test_malformed_delta_does_not_crash` (`test_delta_apply.gd:222–231`) ends in
  `_assert_eq(…, true, true)` twice. The test is unfalsifiable by construction.

**[Med]** Two tests never run:
- `test_quest_steward_presentation.gd` has no PASS sentinel, so it could not be registered as-is.
- `test_weapon_range_tooltip.gd` is simply not registered in `client_smoke.sh`.

**[Med]** The overhaul has almost no live Godot proof. None of the 13 ci-pack client scenarios, and
no scenario added in v469–v484, exercises kit monsters, armor look or kit walls. ADR-0018 D9
accepts human-reviewed screenshots as the visual gate, because headless `gl_compatibility` cannot
see Forward+. The exception is v485, which correctly extended `21_join_game_listed_session.json`.
Prior deferred proofs are still open: no client scenario covers `quest_steward` or skill ground
aim, and `test_inventory_wallet_delta_runtime.gd` still has zero resource-bag/stash cases.

**[Strength]** The new modules have direct unit tests that do not import `MainScript`:
`test_armor_look`, `test_kit_monsters` (texture-preserving tint, `:24–42`), `test_dungeon_kit`,
`test_dungeon_kit_props`, `test_remote_player_class` (164 lines), `test_death_pose_ownership` and
`test_render_environment_presentation`.

## Top 5 client refactors

1. **[High · Test]** Harden the gate before anything else.
   - Make `run_gate` fail on `SCRIPT ERROR` / `Parse Error` in the gate log.
   - Register the two orphan tests and give `test_quest_steward_presentation` a sentinel.
   - Replace the `true, true` asserts with real post-conditions, including `entity_spawn` without
     `id`/`type`.
   - Expect this to surface currently hidden failures, which is the point.
2. **[High · Correctness]** Delete the dead first-person surface.
   - Fix or retire scenario 105.
   - Remove `BotEyeViewAssertions`, the `assert_eye_view_weapon` step and the `bot_facade.gd:280–281`
     hooks.
   - Remove the `first_person_*` parameters in `combat_local_attack_presentation.gd`.
   - Remove `impact_sparks.gd.uid`, the elite-minimap scripts and `rounded_dungeon_corner_capture.gd`.
3. **[Med · Perf]** Fix wall occlusion.
   - Make the interval a real throttle.
   - Limit targets to monsters inside the camera or light radius.
   - Move `sync_occlusion_fade` out of `_refresh_monster_health_bar_visibility` into `_process`
     only.
   - Stop per-spawn raycasts.
   - Add a throttle unit test.
   - Then re-measure the first-spawn hitch and consider merging each wall's kit pieces into one
     mesh for draw calls.
4. **[High · Maint]** Extract `DeltaEventRouter` from `_apply_delta` (the v460 #1 carry-over).
   - Start with a data-driven skill-presentation dispatch keyed from `skill_presentations.v0.json`,
     which removes the `charge`/`earthbreaker`/`heal`/`dash`/`pinning_shot`/`poison_stab` literals.
   - Move the 638-line bot API block out of `main.gd` behind a typed facade to replace the 59
     reflective `_member()` reads.
5. **[Med · Maint]** Consolidate the copy-paste infrastructure.
   - Create one `AssetManifest` static loader with `res_path()`, replacing four production parsers
     and six path mappers.
   - Create one rarity palette loader, replacing five panel copies and two drifting world palettes.
   - Route `LootNodeFactory.apply_model_tint` through `ModelTint`.
   - Fold the rule-8 fixes in `_upsert_entity` into the same slice.
