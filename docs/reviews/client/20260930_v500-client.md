## Summary

This window did real, verifiable debt paydown on the v486 findings, not just feature work. Four of
the five "minor/High Test" findings from v486's Top 5 are now actually fixed, with commits that
match their stated intent: the client gate now fails on `SCRIPT ERROR`/`Parse Error`
(`1958456b`), the two orphan tests are registered, the vacuous `true == true` asserts in
`test_delta_apply.gd` were replaced with real postconditions tied to a genuine bug fix
(`6aba0b84`), and the dead eye-view/first-person surface was fully retired rather than patched
(`86d3b834` — scenario 105 rewritten to assert camera mode + equip + attack outcome, zero
`first_person_*` references remain anywhere in `client/` or `tools/bot/`). The wall-occlusion
throttle is also genuinely fixed (`fb92ac47`): it now returns early unless something changed AND
the min-interval has elapsed, instead of the inverted "rebuild every frame in combat" logic v486
found. The Go race detector was added to CI step 6 as recommended.

What did **not** move: `_apply_delta` is still a single 482-line, 71-branch dispatcher
(`main.gd:1303-1784`) with the same hardcoded skill-id literals (`charge`, `earthbreaker`, `heal`,
`pinning_shot`, `dash`, `poison_stab` all still present) — the v460/v486 #1 and #4 refactor targets
are untouched carryover, not regressions. `bot_facade.gd` still reaches into `main.gd` via 64
reflective `_member()` calls (was 59); the manifest-parsing and rarity-palette duplication v486
flagged are also unchanged. Several near-ceiling panels (`market_panel.gd`, `blacksmith_panel.gd`)
sit exactly where they did at v486 — not worse, but the "touch-to-shrink" ratchet intent still
isn't being honored for them.

The v494-v500 graphics batch (room dressing, frame pacing, lighting, live targeting corrections,
town terrain/nature) is clean on the two things that matter most for this repo's invariants: no
delta-dict bracket access (`c["..."]`/`entity["..."]`) appears anywhere in the new scripts, and no
new script computes gameplay outcomes — all of it is presentation, batched MultiMesh rendering, or
deterministic seeded placement. The new KayKit Forest Nature Pack assets are properly recorded
(CC0, archive SHA-256, per-GLB provenance in `assets/manifests/assets.v0.json`) against the
ADR-0018 D2 allow-list.

## 1. Architecture

**[Strength]** Thin-client boundary still holds. Surveyed every new v494-v500 script
(`dungeon_room_dressing.gd`, `town_ground_detail.gd`, `town_nature_landmarks.gd`,
`live_targeting_trace.gd`, `combat_vfx.gd`, `attack_contact_trace.gd`): placement, scatter, and
targeting-correction logic all read seeded `client.seed|level` keys and existing authoritative
entity state; none of it writes HP, loot, or other outcomes. `town_nature_landmarks.gd:44` uses a
schema-provided `seed_salt` for deterministic scatter rather than `randf()`.

**[High, unchanged from v486]** `_apply_delta` fan-out is still a cohesion hotspot, and grew
slightly: `main.gd:1303-1784`, now **482 lines / 71 `event_type ==` branches** (v486: 473/68).
Hardcoded skill-id dispatch is unchanged — `charge` (`:1385,1821`), `earthbreaker` (`:1409,2450`),
`heal` (`:1424,2395,2400,2412`), `pinning_shot` (`:1461`), `dash` (`:1468`), `poison_stab`
(`:3803`). No `DeltaEventRouter` extraction landed. This is the single largest open item from both
the v460 and v486 reviews, now carried into a third review untouched.

**[Med, unchanged]** `bot_facade.gd` still does reflective `_member(owner, name) → owner.get(name)`
against `main.gd` privates (64 call sites, up from 59; `has_method` duck-typing appears 154 times
repo-wide). This is the same fragility class that hid the dead first-person hooks at v486 — it
happened to not hide anything new this window, but the pattern itself wasn't addressed.

**[Med, unchanged]** Shared-data path-mapping duplication is unchanged: `globalize_path("res://")`
pattern for reading `shared/` from outside the Godot project still appears in 47 files (v486: 44,
now also includes new town/dressing loaders). The "one `AssetManifest` loader" recommendation from
v486's Top 5 #5 was not acted on.

**[Strength, new]** The v494-v500 batch is itself well-factored: each gameplay concern (room
dressing, ground blend, nature landmarks, torch lights, live targeting trace) is its own
`class_name ... extends RefCounted` module with a focused `test_*.gd`, following agent rule 7. None
of it was added inline to `main.gd` — `main.gd`'s net line count actually *fell* in this window
(see Maintainability).

## 2. Technical

**[Resolved since v486]** The dead first-person / eye-view surface is fully retired, not just
patched.
- `tools/bot/scenarios/client/105_eye_view_weapon_presentation.json` was rewritten (`86d3b834`):
  it no longer asserts `equipment_visuals.eye_view`. It now asserts chest-view camera mode, an
  `assert_wall_occlusion` with `active: false`, equip via `item_equipped`, then a real attack
  outcome (`monster_damaged`/`attack_missed`).
- `rg -n "first_person" client/ tools/bot/` returns **zero hits**. `bot_eye_view_assertions.gd`
  (the v486-flagged dead probe) no longer exists in the tree.
- `combat_local_attack_presentation.gd`'s dead `first_person_anim`/`first_person_recorder`
  parameters are gone along with it.

**[Resolved since v486]** Wall-occlusion throttle is now a real throttle.
`wall_occlusion_fade.gd:41-46` — the gate is `if not never_built and (not changed or
_frames_since_rebuild < min_frames): return`, i.e. it skips the rebuild unless something changed
**and** enough frames elapsed, the inverse of the v486-flagged inverted condition. Confirmed by
commit `fb92ac47` ("fix: make the wall-occlusion rebuild throttle actually throttle").

**[Resolved since v486]** Agent rule 8 (`.get()` discipline) violation in `_upsert_entity` fixed.
Commit `6aba0b84` ("fix: ignore entity upserts without id/type; make malformed-delta test real")
now makes `test_delta_apply.gd`'s `_test_malformed_delta_does_not_crash` assert
`"entity upsert without id/type creates no entity"` against `m.entities.size()`, replacing the
prior `true == true` no-op. Spot-checked the new v494-v500 scripts for the same anti-pattern — no
direct `c["..."]`/`entity["..."]` bracket access found in `dungeon_room_dressing.gd`,
`live_targeting_trace.gd`, `combat_vfx.gd`, `town_ground_detail.gd`, `town_nature_landmarks.gd`, or
`attack_contact_trace.gd`.

**[Not evaluated here — carryover, not re-verified]** Ground loot still using
`LootNodeFactory.apply_model_tint`'s flat `StandardMaterial3D` replacement
(`loot_node_factory.gd:390-396` region) was not re-read this pass; `git diff --stat` shows
`test_loot_node_factory.gd` gained 144 lines in v487 ("kit ground loot"), which is the kind of
change that plausibly addresses this — a future review should re-verify whether `ModelTint` is now
routed through loot nodes rather than assume it from the test file's growth alone.

**[Low, new]** `town_ground_detail.gd`'s test file (`test_town_ground_detail.gd`, 446 new lines) is
itself near the 600-line threshold for new files; it is not yet grandfathered and should be watched
on the next review if it grows further.
