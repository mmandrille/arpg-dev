## 1. Architecture

**Strength — thin-client boundary holds.** Boss warnings read the server-authored lane, Ranger UI reads server state, and loot labels resolve presentation catalogs without changing item identity, pickup radius, or authority. New concerns use focused presenter/loader scripts and existing asset-manifest paths.

**High maintenance — `_apply_delta` remains a large event dispatcher.** `main.gd:1308-1784` still mixes snapshot-adjacent state updates, a broad event branch tree, UI refreshes, and combat presentation. It is now 6,645 lines (17 more than v500). Extracting a typed domain router is a multi-module change and should retain event ordering, ignored-event behavior, and dirty-field synchronization.

**Medium — boss reconnect visual state is not proven.** The live presentation consumes phase start/end events, but a reconnect snapshot may not recreate the active telegraph consistently. v509's as-built leaves live reconnect partial; the ordinary reconnect scenario passing does not exercise a boss caught mid-warning. Add a focused reconnect-at-phase scenario before claiming this behavior.

The recent batch mostly added isolated helpers, but presentation additions still increase the amount of state that the coordinator must route. `BotFacade` reflection and repeated catalog-loading patterns remain separate follow-up candidates; the specialists did not identify a safe automatic replacement that preserves all call sites.
