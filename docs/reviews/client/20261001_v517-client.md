## Summary

The batch is disciplined presentation work: new logic landed in small, directly importable modules with their own unit tests (14 new/updated gates in the fast smoke), `main.gd` grew by only nine lines net, and `inventory_panel.gd` shrank 1,623 → 1,111 with the baseline lowered to match (`.maintainability/file-size-baseline.tsv:9`). The thin-client boundary holds: nothing reads or writes server state, and the only authority-adjacent change is the client choosing boss model/scale/tint from a client catalog keyed by the server's `boss_template_id`.

What the batch does **not** have is runtime proof of the new visuals in the gate that ran. All five new client bot scenarios (`111_boss_intro_banner_cave_warden`, `112_boss_intro_banner_crypt_matron`, `113_hud_polish_visual`, `monster_windup_pose`, `v511_monster_variant_pack`) are `ci_tier: extended` (`docs/progress/scenario-movement-audit.tsv`; none appears in `tools/bot/ci_pack.json`), so the fast `make ci` exercised them zero times, and `make ci-full` was not run. What `make ci` did give: 14 new unit gates plus the existing fast client scenarios (`click_to_kill`, `inventory_equip_unequip`, `account_stash_panel`, `model_reaction_polish`, `market_board_ui`) as regression coverage over the edited `main.gd`/inventory/stash paths.

The theme migration is half-finished by design (v514's as-built says so) and the unfinished half is now the main maintainability risk: two theming systems (`UiTheme`/`HudStyle` and per-panel private literals) coexist, and the new `InventoryTooltipContent` itself bypasses the theme.

## 1. Architecture

- **[Strength] Thin-client boundary preserved.** `monster_anim_driver.gd`, `monster_variant_look.gd`, `boss_presentation_*.gd`, `hud_*.gd` read wire fields only. Animation stays client-only presentation (ADR-0007): hooks in `main.gd` are `:1347` (live spawn), `:1394` (windup), `:1766` (event clip routing), `:2351` (hide variant aura on death), `:5525`/`:5544` (entity node construction).
- **[Strength] Pure, typed seams with direct tests.** `InventoryTooltipContent` takes a narrow `Context` object (`client/scripts/inventory_tooltip_content.gd:17-24`) instead of the panel; `HudLayout` is pure rect math with a no-overlap test across 1024x576–2560x1440; `MonsterAnimVariants` is pure math (47 checks); `BossPresentationLoader` has `set_bosses_for_test`/`reset_for_test` hooks. This follows the extraction-independence rule (no `globals()` laundering; `make maintainability` reports 0 coupled helper injections).
- **[Med] Client overrides server visual metadata for bosses.** `BossPresentationLoader.effective_scale/base_tint/make_root` (`boss_presentation_loader.gd:55-60`, `:63-66`, `:75-95`) replace the wire `visual_scale`/`visual_tint`/`visual_model` whenever the template is catalogued; call sites `main.gd:1979`, `:5525`, `:5588`, `:5593`, `:5781`. This is a legitimate presentation-only choice, but the server still emits and validates its own boss look (`shared/rules/boss_templates.v0.json:15-20`), so the repo has two boss-look sources of truth with no cross-check beyond "every template has a presentation entry" (`tools/validate_boss_presentation.py`).
- **[Med] `_apply_delta` keeps absorbing domain hooks.** `main.gd:1310-1794` (485 lines) gained three more `MonsterAnimDriver` call sites plus a spawn-detection local (`:1344-1347`). Each hook is small, but ordering relative to `_upsert_entity` and the event loop is implicit; there is still no event-router seam or ordering test (carried from v510).
- **[Med] Spawn-in animation is gated on `entity_spawn`, which also means fog reveal.** `main.gd:1344-1347` fires `MonsterAnimDriver.on_live_spawn` for any new `entity_spawn` op; `monster_anim_driver.gd:124-146` excludes level-arrival batches (`wall_layout_update`), off-frustum, dead, disabled-profile, and caps at 4 concurrent clips, but cannot distinguish a monster that spawned from one revealed by fog. Server confirms the op is a generic spawn (`server/internal/game/types.go:518`). The as-built flags this; no in-play capture shows how it reads. `spawn.enabled=false` is the opt-out.

## 2. Technical

- **[Strength] Redraw discipline in the new HUD.** `hud_globe.gd` has no `_process` and redraws only through `_request_redraw()` on change (`hud_globe.gd:21-52`, `:66-69`); `flash` uses one tween. Variant looks are built once at node creation with shared cached materials (`monster_variant_look.gd`, header comment and `_remember` cap 256).
- **[Low] Boss presence does avoidable allocation on every delta/snapshot.** `sync_at_tick` (`boss_visuals_controller.gd:23-26`) runs on every snapshot and delta (`main.gd:1263`, `:1784`, `:2132`), each pass walks all entities (`boss_visuals_controller.gd:70-81`) and `BossArenaPresence.sync_for_record` calls `_aura_config` twice (`boss_arena_presence.gd:34`, `:142`), each of which does `BossPresentationLoader.entry()` → `Dictionary.duplicate(true)` (`boss_presentation_loader.gd:53`). The mesh rebuild is correctly keyed (`boss_arena_presence.gd:44-49`), so this is dictionary churn, not draw cost; it is small per boss but unnecessary. `base_tint`/`effective_scale` also deep-copy per entity upsert.
- **[Med] Boss draw cost is unmeasured in play.** The v512 as-built measured an isolated scene (legacy 2 draw calls / 708 primitives vs Cave Warden 20 / 8,686 and Crypt Matron 12 / 7,067) and states no matched in-dungeon A/B was taken. Each boss also adds an `OmniLight3D` in the full-quality tier (`boss_arena_presence.gd`, `_sync_aura_extras`). Boss floors are rare and compact, so this is likely fine, but it is a claim, not a measurement.
- **[Med] HUD adds +16 draw calls.** v517 A/B: 108 → 124 draw calls, +4% primitives, frame p50/p95 unchanged — on an Apple M4 Pro, vsync-capped at 60 Hz, so sub-vsync cost and weaker GPUs are invisible (`docs/as-built/v517_hud-hotbar-polish.md`, Evidence/Limits). `HudGlobe._draw` issues two circles, a polygon, a line, two arcs, plus text outline and text per globe (`hud_globe.gd:75-99`); the as-built itself suggests merging commands.
- **[Low] Variant look cache clears wholesale at 256 entries** (`monster_variant_look.gd:128-131`), keyed on source material instance id; materials already assigned to nodes stay alive, so this is cache thrash at worst, not a leak. The v511 full sweep creates 76 materials, far below the cap.
- **[Med] UiTheme failure mode is a magenta paint plus one `push_error`.** Unknown tokens return `FALLBACK_COLOR` (`ui_theme.gd:8`, `:82-83`, `:101-102`). My ad hoc scan of literal `UiTheme.color/spacing/frame("...")` call sites against `ui_theme.v0.json` found no missing literal tokens today (two prefix-concatenated lookups in `inventory_panel_styles.gd:33,37` are covered by `validate_ui_theme.py`'s per-rarity checks), but nothing in CI enforces client call-site tokens against the catalog; the validator only checks catalog-internal references (`tools/validate_ui_theme.py:15-40`).
- **[Low] Fonts are not on the theme.** `fonts` entries are reserved placeholders; the only consumer is `character_panel_styles.gd:35-43` (`UiTheme.font_size`). `hud_globe.gd:94` uses `ThemeDB.fallback_font` with literal sizing.

## 3. Maintainability

- **UiTheme adoption is incomplete (verified).** Files referencing `UiTheme`: `ui_theme.gd`, `character_panel_styles.gd`, `inventory_panel_styles.gd`, `hud_style.gd`, `boss_bar_frame.gd`. HUD files go through `HudStyle` (which itself resolves `hud_*` tokens). Remaining panels with private style tables and hard-coded `Color("#…")` literals (counts of `Color("#` lines): `shop_panel.gd` 27, `stash_panel.gd` 27, `market_panel.gd` 23, `skills_panel.gd` 18, `blacksmith_panel.gd` 17, `item_tooltip_panel.gd` 13, `skill_bar.gd` 9, `character_select_panel.gd` 6, `stat_tooltip_label.gd` 5, `main_menu.gd` 2; plus `StyleBoxFlat.new()` sites in `skills_panel.gd` (4), `shop_panel.gd` (3), `stash_panel.gd`, `market_panel.gd`, `consumable_bar.gd` uses `HudStyle` but keeps one literal (`consumable_bar.gd:48`). The new `inventory_tooltip_content.gd` itself has 9 literal colors (e.g. `:81`, `:102-110`, `:349-367`), duplicating values that also appear in `market_panel.gd:937` and `stash_panel.gd:974` (`#cdbd9f`).
- **Item tooltip logic is forked four ways.** Only `inventory_panel.gd:651-729` uses `InventoryTooltipContent`; `stash_panel.gd:970`, `shop_panel.gd:760`, and `market_panel.gd` keep their own `_tooltip_lines`. The "tooltip redesign" therefore applies to the inventory panel only.
- **Rarity tables are duplicated.** `ClientConstants.LOOT_LABEL_RARITY_COLORS` (`client_constants.gd:38-44`) equals the theme's `inventory_rarity_*` colors (`shared/assets/ui_theme.v0.json:36-40`); parity is enforced only by a client unit test (`client/tests/test_inventory_tooltip_content.gd:100-105`). Other rarity color/background tables remain in `client_constants.gd` (lines 28-61), `shop_panel.gd:42-47` and `stash_panel.gd:38-39` (four rarities, no `set`, while the theme defines five), and `equipment_visuals.gd:35`. The v515 as-built justifies the const (cannot call `UiTheme`), but `loot_node_factory.gd:264` is a function that could.
- **`main.gd` at 6,654 lines** (baseline 6,632; `+22`, inside the +25 allowance) after a batch that edited it in v511, v512, and v513. Growth is now almost entirely allowance; the next edit needs extraction first (`PROGRESS.md` says so).
