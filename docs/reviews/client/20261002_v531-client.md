## Summary

The client remains a thin presentation layer: server snapshots and deltas own gameplay state, while local movement prediction feeds intent and reconciles against server positions. Panels signal intent to the coordinator rather than authoritatively mutating game state. Client bot and replay paths provide broad deterministic coverage.

One concrete freshness bug exists in bot event observation: multiple state-delta envelopes may be coalesced, but their individual envelope ticks are discarded. Each event in the merged payload receives the newest global tick, so an older event can satisfy a later bot step's “since step start” condition. The main delta coordinator and inconsistent tooltip/theme ownership remain maintainability concerns.

## 1. Architecture

- **[Strength] Thin-client authority boundary holds.** Snapshots and deltas update state (`client/scripts/main.gd:1231-1299,1310+`); predicted movement is presentation-only and reconciles with server positions (`main.gd:1889-1943`).
- **[Strength] Panels express intent.** The inventory panel delegates intent to the main coordinator (`main.gd:3918-3920,4204-4212`); no client-side authoritative mutation was found in the inspected flow.
- **[Med] `_apply_delta` remains an ordered, 483-line coordinator.** It handles state changes, event routing, UI synchronization, bot observations, and movement reconciliation (`main.gd:1310-1792`). Splitting it requires explicit ordering and coverage.
- **[Med] Runtime scene construction centralizes many UI controls.** `_build_scene` creates and wires more than 25 HUD/panel controls (`main.gd:3867-3999`), increasing the cost of changing panel composition.

## 2. Technical

- **[Med] Coalesced bot events inherit the newest envelope tick.** `_handle_message` updates `last_server_tick` for each envelope but queues only its payload (`main.gd:1126-1134`). `_flush_pending_deltas` merges payloads (`main.gd:1150-1155`; `delta_frame_coalesce.gd:5-19`), then `_apply_delta` tags every merged event with the final `last_server_tick` (`main.gd:1773-1778`). Bot waits filter event freshness against `step_start_tick` (`bot_wait_handlers.gd:173-185,193-203,273-279`; `bot_scenario_runner.gd:90-93`). An earlier event in the same coalesced frame can be misclassified as new. Preserve source tick per delta/event and test a two-envelope boundary case.
- **[Strength] Replay presentation uses recorded timeline envelopes.** Visual replay feeds timeline data through normal message handling (`main.gd:3710-3720,3779-3813`).
- **[Evidence limit]** The room-door visible scenario replay matched, but the Godot runner emitted resource/ObjectDB shutdown warnings and no retained image establishes the visual result.

## 3. Maintainability

- **[Med] `main.gd` remains large at 6,654 LOC.** A typed state reducer and ordered presentation-event router are plausible seams, but should be extracted in phases with event-order tests.
- **[Med] Tooltip and styling ownership is inconsistent.** `shop_panel.gd` duplicates rarity colors and tooltip/style logic (`:15-47,780,1161-1204`); `stash_panel.gd` has parallel logic (`:967-1017,1116+`), as does `market_panel.gd` (`:937-946,1039-1069`). `InventoryTooltipContent` and `UiTheme` already exist but adoption is incomplete (`inventory_tooltip_content.gd:26-43`, `ui_theme.gd:1-5`).
- **[Strength] Existing tests cover delta mutations and coalescing**, but `test_delta_frame_coalesce.gd:16-31` does not pin source-tick ownership or event ordering, allowing the freshness issue above to escape.
